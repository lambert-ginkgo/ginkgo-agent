## 1. 产品概述

### 1.1 背景与问题

IT 服务台是企业内最高频、最机械的求助场景：密码重置、VPN 连不上、权限申请、设备报修。传统工单系统的痛点：

1. **入口重**：员工要先分清"这事找谁"，自己选分类、填表单，求助门槛高
2. **两张皮**：知识库（FAQ/文档）和工单系统割裂，员工不知道知识库里早有答案，IT 重复回答同样的问题
3. **流转慢**：工单创建→分派→响应的链条里，前两步本来就不需要人

LLM Agent 的机会正好在这三步：**自然语言描述问题**（免表单）、**知识库检索直答**（免重复）、**理解-分类-建单**（免人工录入）。ginkgo-agent 把这条链路做成一个企业 IM 里的机器人。

### 1.2 产品定位

**一句话**：面向中小团队的 IT 服务台智能体——员工一句话描述问题，Agent 完成理解、答复、建单、流转的全链路。

**明确不是**：不是通用聊天机器人（只在 IT 服务台域内工作）；不是自动运维工具（MVP 不执行修复动作，只做信息服务与流转）；不替代工单系统（MVP 自带轻量工单，第二季再考虑对接企业现有工单系统）。

### 1.3 目标用户

| 角色 | 说明 | 核心诉求 |
| --- | --- | --- |
| 员工（求助者） | 遇到 IT 问题的一般员工 | 一句话说清问题就有人管；问题有答案就直接给我；随时知道进度 |
| IT 工程师（处理者） | 接单处理的一线 IT | 高频问题别再进工单队列；进来的工单已分类、有摘要、有上下文 |
| 管理员 | 维护知识库与权限的 IT 负责人 | 知识库可维护；谁能看什么可控制；运行情况可观测 |

### 1.4 核心价值主张

- 对员工：**首响时间从"小时级"到"秒级"**，高频问题即时解决
- 对 IT：**重复问题被知识库拦截**，人工只处理真正需要人的部分
- 对团队：**求助数据沉淀**——什么问题最多、知识库缺什么，看得见

## 2. 用户角色与核心场景

### S1 标准问题直答（高频）

> 员工：`密码忘了怎么重置`
> Agent：检索知识库命中《密码重置指南》，直接给出步骤（附出处），不建单。
> **验证点**：知识库命中率内的问题不进工单队列。

### S2 排查交互（中频）

> 员工：`VPN 连不上`
> Agent：先反问关键信息（内网/外网？报错截图？），根据回答检索知识库给出排查步骤；若仍未解决，征询确认后建单，把排查过程作为工单上下文带给 IT 工程师。
> **验证点**：多轮追问补全信息；建单时携带对话上下文。

### S3 权限申请（必建单）

> 员工：`帮我开通 Confluence 的编辑权限`
> Agent：识别为申请类需求（知识库解决不了），抽取字段（申请人、申请对象、事由）生成工单摘要，员工确认后落库。
> **验证点**：意图分类正确；字段抽取准确；确认后才落库（不静默建单）。

### S4 进度查询

> 员工：`我上周提的那个单子怎么样了`
> Agent：从会话记忆定位工单（指代消解），调用查询工具返回状态与处理人。
> **验证点**：跨轮次的指代理解；只能查到本人权限内的工单。

## 3. MVP 范围边界

**In scope（第一季 E01-E11 交付）**

- 单租户部署，三角色（员工 / IT 工程师 / 管理员）
- 企业 IM 单平台接入（平台由系列共创投票决定：钉钉 / 企业微信 / 飞书）
- 多轮自然语言对话 + 工具调用（查单/建单）
- 轻量知识库（文档上传 → 切分 → 检索 → 带出处的回答）
- 轻量工单（创建/查询/状态流转，不包含分派引擎与 SLA）
- 角色数据权限（员工只见自己的工单）
- 低置信度转人工（HITL）
- 可观测（对话日志、调用链、token 成本）
- Docker 一键部署

**Out of scope（明确不做，第二季候选）**

- 多租户 SaaS 化
- 工单分派引擎、SLA 自动升级
- 自动执行修复动作（remediation，如真的去重置密码）
- 对接企业现有工单系统（Jira/ServiceNow 等）
- 语音、多模态输入
- A2A 多 Agent 协作

> 范围纪律：第一季的敌人是"功能蔓延"。每集只做当集模块，PRD 变更走第 9 节决策记录。

## 4. 功能需求

模块编号 M1-M11 与系列集数 E01-E11 一一对应（E12 为系列复盘，不产生功能）。需求编号 `FR-M<模块>-<序号>`，优先级：P0 = MVP 必须且当集交付；P1 = 当集交付但可简化（合并集时的降级候选）。

### M1 对话基座（E01）

**需求**：提供命令行的多轮对话入口，接入 DeepSeek 模型，流式输出。（本地 HTTP 入口随 E09 Web 框架引入，见 Q6）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-M1-01 | 用户可发起多轮对话，Agent 基于模型生成回复 | P0 |
| FR-M1-02 | 回复流式输出（打字机效果） | P0 |
| FR-M1-03 | 模型 API Key、模型名外置于配置文件，不硬编码 | P0 |
| FR-M1-04 | 会话可重置（清空上下文重新开始） | P1 |

**验收标准**：命令行发起对话，3 轮内上下文保持正确；拔掉 Key 配置启动时给出明确错误提示而非堆栈；流式输出肉眼可见逐步呈现。

### M2 工单查询工具（E02）

**需求**：Agent 具备第一个工具调用能力——查询 mock 数据源中的工单。

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-M2-01 | 提供"查工单"工具：按工单号返回状态、标题、处理人、创建时间 | P0 |
| FR-M2-02 | 提供"查我的工单列表"工具：按用户返回其名下工单摘要（E02 CLI 期"我"固定为 mock 数据源默认用户，E07 起由 FR-M7-01 模拟身份提供） | P0 |
| FR-M2-03 | Agent 自主决定何时调用工具（用户问工单即调，闲聊不调） | P0 |
| FR-M2-04 | 工具结果回传模型后，Agent 能基于结果组织自然语言答复（不吐原始 JSON） | P0 |

**验收标准**：问"工单 1024 什么状态"返回人话答复；问"今天天气"不触发工具调用；工具数据源为 mock（内嵌测试数据），接口抽象使后续替换真实存储零改动。

### M3 会话记忆（E03）

**需求**：多轮对话中保持与利用上下文。

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-M3-01 | 跨轮指代消解："它/那个单子"能解析到上文提到的工单 | P0 |
| FR-M3-02 | 记忆范围受控：会话隔离（不同用户的对话互不可见） | P0 |
| FR-M3-03 | 长对话不失控：上下文超限时按策略截断，且优先保留最近轮次与关键实体（工单号等） | P1 |
| FR-M3-04 | 追问策略：信息不足时 Agent 主动追问（一句话内问清），而非带着残缺信息硬答 | P1 |

**验收标准**：S4 场景走通（"我上周提的那个单子"正确解析）；两个用户并发对话无串话；构造 50 轮超长对话，第 1 轮的工单号在第 50 轮仍可被追问引用；若启用截断策略，截断规则与关键实体保留清单须随当集文档公开，且工单号类实体在截断后仍可被引用。

### M4 知识库问答（E04）

**需求**：上传 IT 常见问题文档，检索增强生成答案。

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-M4-01 | 管理员可导入文档（Markdown 纯文本起步）作为知识源 | P0 |
| FR-M4-02 | 文档切分与向量化入库；知识库更新后新问题能命中新内容 | P0 |
| FR-M4-03 | 员工提问命中知识时，答案附带出处（文档名/片段定位） | P0 |
| FR-M4-04 | 知识库未命中时，Agent 明确说"知识库里没有"并给下一步建议（建单/转人工），**禁止编造** | P0 |
| FR-M4-05 | 检索质量可观测：返回相似度阈值，低于阈值视为未命中 | P1 |

**验收标准**：S1 场景走通（密码重置直答带出处）；问一个知识库中没有的问题，答复中明确包含"没有找到"类表述且不编造步骤；导入新文档后立即命中。

### M5 智能建单（E05）

**需求**：自然语言求助转化为结构化工单。

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-M5-01 | 意图分类：直答 / 排查 / 建单 / 查询 四类意图，分类错误有兜底（默认走排查） | P0 |
| FR-M5-02 | 建单字段抽取：分类、优先级（高中低）、标题、摘要，从对话中抽取 | P0 |
| FR-M5-03 | 落库前向员工展示工单卡（字段确认/修改），**确认后才创建** | P0 |
| FR-M5-04 | 工单携带对话上下文摘要，IT 工程师接单时可见"已排查过什么" | P1 |

**验收标准**：S3 场景走通；抽取的字段在确认卡中可人工修改；构造模糊描述（"电脑坏了"）时 Agent 追问而非瞎猜优先级；建单成功返回工单号。

### M6 流程编排（E06）

**需求**：将"意图识别 → 检索/建单 → 答复 → 升级"固化为确定性工作流（Graph）。

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-M6-01 | 核心链路以图编排实现（节点：意图路由 / 知识检索 / 建单 / 人工升级 / 答复组装） | P0 |
| FR-M6-02 | 直答与建单路径分叉正确（S1 走直答支路，S3 走建单支路） | P0 |
| FR-M6-03 | 流程节点执行轨迹可查询（走了哪些节点、每步耗时） | P1 |

**验收标准**：S1/S3 两场景分别命中正确支路；用 20 条混合意图测试集跑通无死循环；节点轨迹可在日志中还原。

### M7 权限控制（E07）

**需求**：角色与数据范围控制。

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-M7-01 | 用户身份识别：消息携带用户身份，Agent 知道"和谁说话"（E07 CLI 期以会话参数/配置模拟当前用户，E09 随 M9 切换为 IM 平台透传） | P0 |
| FR-M7-02 | 数据范围：员工仅能查询/操作本人工单；IT 工程师可查询全部 | P0 |
| FR-M7-03 | 工具级放行：危险操作（删单、改他人工单）按角色拦截，拦截有明确话术 | P0 |
| FR-M7-04 | 提示注入基础防护：用户消息中"忽略之前指令"类内容不改变 Agent 角色与权限 | P1 |

**验收标准**：员工 A 无法查到员工 B 的工单（工具层拦截而非仅提示词约束）；构造注入攻击话术，Agent 权限行为不变；IT 工程师查全部工单正常。

### M8 人工转接（E08）

**需求**：Agent 知道自己不行的时候，把人接进来。

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-M8-01 | 转接触发条件：低置信度 / 连续 2 次未解决 / 用户明确要求 / 知识库未命中且用户拒绝建单 | P0 |
| FR-M8-02 | 转接动作：工单标记"待人工"，经通知通道通知 IT 工程师，附带完整对话上下文摘要（通知通道接口抽象：E08 以日志/CLI 模拟通道验收，E09 随 M9 替换为真实 IM 通道） | P0 |
| FR-M8-03 | 转接后 Agent 退位：该会话标记为人工接管，Agent 不再抢答（直到工程师关单） | P1 |
| FR-M8-04 | 用户可随时主动说"转人工"立即触发 | P0 |

**验收标准**：四类触发条件各构造一例全部走通；IT 工程师收到的通知包含问题摘要与已排查内容（E08 模拟通道下通知落日志/控制台，内容可核验）；人工接管期间 Agent 不插话。

### M9 IM 接入（E09）

**需求**：Agent 进入企业 IM，成为服务台入口。

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-M9-01 | 支持在 IM 群中 @机器人 触发对话，也支持私聊 | P0 |
| FR-M9-02 | 消息回调鉴权（校验平台签名，防伪造消息） | P0 |
| FR-M9-03 | IM 身份 ↔ 系统用户映射（拿平台 user id 定位角色与数据权限） | P0 |
| FR-M9-04 | 平台适配层抽象（回调解析、消息发送接口隔离），支持第二季扩展第二平台 | P1 |

**验收标准**：群内 @ 与私聊两种入口均走通 S1-S4 场景；伪造回调（错签名）被拒绝并记日志；同一用户在群聊与私聊中的工单权限一致。
**注**：目标平台（钉钉/企业微信/飞书）由系列共创投票决定，投票结果记入第 9 节决策记录；适配层抽象保证平台选择不影响其余模块。

### M10 可观测与成本（E10）

**需求**：每一次对话可追踪、可复盘，成本可统计。

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-M10-01 | 对话日志：全量对话留痕（用户消息、Agent 回复、工具调用、耗时） | P0 |
| FR-M10-02 | 调用链：一次请求的完整轨迹（入口→节点→工具→模型）可按 traceId 串联查询 | P0 |
| FR-M10-03 | 成本统计：按天/按用户统计 token 消耗与估算成本 | P1 |
| FR-M10-04 | 运营简报：知识库命中率、建单量、转人工率、意图分类分布（管理员可查） | P1 |

**验收标准**：任取一段历史对话，能按 traceId 还原完整调用轨迹；成本报表数字与模型端账单量级吻合（抽样核对）；四项运营指标可出数。

### M11 部署与上线（E11）

**需求**：MVP 可被复制部署。

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-M11-01 | Docker 化：`docker compose up` 一条命令拉起全部组件 | P0 |
| FR-M11-02 | 配置外置：模型 Key、IM 凭证、知识库路径全部走环境变量/配置文件 | P0 |
| FR-M11-03 | 健康检查与启动自检（依赖就绪探测，缺配置时启动期报错并指明缺什么） | P1 |
| FR-M11-04 | 部署文档：从零到跑通的 README 步骤（读者可复现） | P0 |

**验收标准**：在一台干净机器（或全新容器环境）上按 README 操作 30 分钟内跑通；故意缺一个环境变量，错误信息直接指明缺失项；`docker compose down && up` 后工单与知识库数据不丢（持久化卷）。

## 5. 数据模型（概念级）

| 实体 | 关键字段 | 说明 |
| --- | --- | --- |
| 工单 Ticket | id、标题、摘要、分类、优先级、状态（新建/处理中/待人工/已解决/关闭）、创建人、处理人、上下文摘要、创建/更新时间 | MVP 轻量实现，存储选型见第 9 节开放问题 |
| 知识文档 Doc | id、标题、内容、切片数、来源、更新时间 | Markdown 起步 |
| 会话 Session | id、用户、渠道（CLI/IM）、状态（Agent 接管/人工接管）、消息历史 | 渠道隔离 |
| 用户 User | id、IM 平台 id、姓名、角色（员工/IT 工程师/管理员） | MVP 可静态配置 |

> 概念模型仅供对齐，不约束实现（每集动笔时按框架能力落地具体存储结构）。

## 6. 非功能需求

| 编号 | 类别 | 需求 |
| --- | --- | --- |
| NFR-01 | 性能 | 流式首 token ≤ 3s（DeepSeek 常规负载）；单轮完整响应 ≤ 30s，超时有话术兜底 |
| NFR-02 | 安全 | 模型 Key 等凭证不进代码库与日志；工具调用受角色权限约束（M7）；用户输入不直接拼接进系统提示词 |
| NFR-03 | 可靠性 | 模型调用失败自动重试与降级（利用框架容错能力，具体机制以官方文档为准）；工具失败时向用户明确报错而非静默吞掉 |
| NFR-04 | 可观测 | 结构化日志（含 traceId/会话 id）；错误日志带上下文，可定位到对话轮次 |
| NFR-05 | 成本 | 单次常规对话（含一次检索）成本可控；成本统计口径透明（M10） |
